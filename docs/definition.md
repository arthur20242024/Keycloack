## Definition

### Protocols
- OAuth2: authorization protocol. Lets an application a limited ressource whithout knowing the user' password. 
- OIDC: authentication layer builon top of OAuth2. Answers "Who is the user". 
- SAML: older delegated-authentication protocol, based on XML. Does broadly the same job as OIDC but designed for enterprise use, not modern web apps. 
- Delagated authentication: principle where an application never verifies a user's identity itself, and fully trusts a third party (Keycloak) to do it.

### Flow and security
- Autorization code: temporary, single-use code issued by Keycloak right after login, later exchanged for tokens. 
- PKCE: security mechanism that protects public clients. A secret is generated upfront, only its fingerprint(code_challenge) is sent, and the secret is revealed onnly at the final exchange. 
- code_verifier: the random secret generated by the app before login, never sent in clear text before the final exchange.
- code_challenge: the hashed version of the code_verifier, sent to Keycloak at the start of the flow. 

### Tokens 
- JWT: signed token made of three parts (header, payload, signature), base64-encoded and separated by dots. 
- Claim: a single piece of information inside a JWT's payload, e.g. sub, name, roles, exp. 
- Access token: JWT describing what an application is allowed to do. Ready by an API to authorize or deny a request.
- ID token: JWT describing who the user is. Read by the frontend to display their identity. 

### Keycloak
- Realm: a fully isolated space within Keycloak, with it's own users, clients and roles.
- Client: an application registereed withinn a realm, authorized to request tokens from Keycloak
- Confidential client: a client type able to keep a seret (client_secret), because it runs on a server, never exposed to the public. 
- Public clint: a client type unable to keep a secret, because its code runs in the browser. Uses PKCE instead.
- client_id: a client's public idnetifier, visible to everyone, not secret.
- client_secret: a confidential client's secret password, known only to it and Keycloak. 
- Role: a label assigned to a user defining what they're allowed to do. 
- User: an account whithin the realm, with credentials managed by Keycloak and one or more assigned roles.
